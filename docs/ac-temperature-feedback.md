# 空調溫度回饋補償（系統 v1.42.1）

這是可選的外部室溫補償，不是自動開關機規則。預設關閉；在 Dashboard 的空調控制區展開「溫度回饋補償」，選擇同位置的感測器、勾選啟用並保存。首頁釘選空調與裝置頁共用此面板。Apple Home 只操作原有電源、模式及舒適目標，不提供這些進階設定；現有 Homebridge 插件 1.1.0 不需更新。

## 三種溫度

- **感測室溫**：選定外部感測器的有效讀值。
- **舒適目標**：Dashboard、Apple Home、LINE／Siri 共用的使用者目標，仍存於 `最後溫度`。相對調溫也以此值計算。
- **IR 下發**：最近一次確認由設備服務接受的設定溫度，不代表讀回冷氣內部溫度。補償只改此值。例如目標 26°C、室溫 28°C，可逐步下發 25°C；面板目標仍顯示 26°C。

## 進階設定

| 設定 | 預設 | 允許範圍 |
| --- | --- | --- |
| 評估間隔 | 5 分鐘 | 整數 5–30 分鐘 |
| 容許溫差 | ±0.5°C | ±0.3–2°C |
| 每次調整 | 1°C | 整數 1–2°C |
| 最短調整間隔 | 10 分鐘 | 整數 5–60 分鐘 |
| 最大補償 | ±3°C | 整數 ±1–5°C |

`main.py` 每 60 秒執行 `ac-temperature-feedback` 工作，各設備再依評估間隔判斷。感測器沿用既有約 5 分鐘輪詢，這個工作不額外呼叫感測器 API。相同時間戳記的樣本不重複調整；過期超過 11 分鐘、離線、時間在未來或溫度無效都暫停。工作排程與外部服務延遲會影響實際時間。

只在最新 Sheet 記錄為 `on` 且模式為冷氣／暖氣時補償。室溫偏高就降低 IR 設定，偏低就提高，限制在舒適目標正負最大補償且不超過 16–30°C。達到容許範圍後保持既有補償，不立即歸零。送風、除濕、防黴送風不參與；原有自動關機及防黴排程仍各自運作，背景補償不重置開機時間或重建排程。

啟用時按「保存並立即評估」，先保存設定，再用目前感測資料評估一次；保存後按「立即評估」只評估該台已保存的設定，不覆蓋設定。這會略過背景評估週期與部署後等待，但仍保留上次實際命令的最短調整間隔、同樣本不重複發送、電源／模式／資料有效性與待確認限制。符合條件才發送一次 IR，畫面會顯示調整或略過原因。首次配置也會參考既有 `最後更新時間`，剛手動操作過仍須等反應。

停用只停止後續補償，保留已下發設定，不立即評估或發送 IR。下次透過管家／Dashboard／Apple Home 送出的成功開機或調整命令會重新以舒適目標下發，再等待反應；不保留舊補償。背景工作重新部署後仍先等待最短調整間隔，不密集補跑漏掉的週期。

## 保存與失敗行為

首次保存時，在「智能居家」自動加入 `空調溫度回饋設定`、`空調溫度回饋狀態` 兩個 JSON 欄位。一般讀取不建立欄位；未配置家庭的背景工作沒有新增 Sheets I/O。配置後的手動控制增加狀態確認與保存，以維持舒適目標及 IR 記錄一致。

發送前先保存待確認標記，保存失敗就不發送。設備回應或完成保存結果不確定時停止補償，不自動重送；待確認標記保留跨重啟。檢查設備後，手動送出一次完整設定並成功保存才恢復，切換補償開關不能清除此標記。欄位遺失、設備名稱／ID 重複、感測器移到不同位置均拒絕調整。

`GET /api/ac/feedback` 回傳空調設定、狀態、三種溫度及可選感測器名稱／位置；`POST` 接受 `device_name`、選填 `config` 與布林 `evaluate_now`（預設 false）。只傳 config 維持純保存的舊契約；另傳 `evaluate_now: true` 才立即評估，回應含 `evaluation.status`。省略 config 可只評估後端當前設定；兩者皆未提供則 422。保存失敗不評估，未知發送結果保留待確認，不自動重送。後端只接受 owner API key，Homebridge／家電語音 Key 無權使用。Dashboard BFF 額外驗證成員 Session，kid 帳號不可讀寫。沒有加入 LLM 工具或新的語音動作。

IR 無實體狀態讀回：若拿原廠遙控器關機，後端可能仍記為開機，之後的完整 IR 指令可能再次開啟。啟用期間應透過 Dashboard、Apple Home 或管家操作關機。這項限制不能單靠感測室溫消除。

AC 控制與設定共用同一程序的 RLock；Homebridge 也共用此鎖，避免背景調整與手動關機交錯。部署仍限定單一 worker／實例；Google Sheets 外部直接編輯不受此鎖保護，也沒有跨程序交易保證。

## 驗證與復原

`tests/test_ac_feedback.py` 使用 fake Sheets／SwitchBot 驗證控制方向、邊界、過期樣本、開關及模式限制、重啟、未知結果、並行控制與 API 金鑰邊界。`test_sheets_reuse.py` 驗證補償標記與一般狀態同批保存、缺欄不部分寫入；Homebridge 投影測試確保舒適目標不被 IR 溫度覆蓋。

先部署後端，再部署 Dashboard。日常停用用 Dashboard 開關；若要回退舊程式，先停用並手動送出想要的溫度，再回退 Dashboard 和後端。新增 Sheet 欄位可保留，不需刪除。模擬測試不等於實際房間溫控驗收，第一版需觀察真實冷氣反應後再調整參數。
