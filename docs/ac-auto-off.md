# HB 空調自動關機（v1.57.0）

時數只在智能居家分頁既有「自動關機小時數」欄位管理：0／空白停用，1–168 整數小時。
非法值視為停用；不新增 Sheet 欄位、HA 自動化或 HA 權限。
Dashboard 移除時數設定，改在既有排程區編輯、刪除本輪產生的排程。

## 計時與編輯

- HB 每 60 秒觀察 HA 快照；首次確認 on 時依 Sheet 建立一次性 off，來源「自動（HA）」。
- 初次接手已開機空調從觀察時計時，不使用遷移前的最後開機紀錄；Dashboard／HA／Apple Home 開機同樣適用。
- 調溫、風速、模式切換不重新計時。Sheet 正值時數的修改適用下一輪，避免覆寫已編輯的本輪排程。
- Dashboard 可修改本次時間、同一台空調的控制參數或刪除；Sheet 的預設時數不變。
- 刪除後留下不顯示在 UI 的已取消紀錄，本輪不再補建，即使 Render 重啟或狀態仍 on。
- Sheet 改為 0 取消本輪尚未執行的排程；再改正值仍等下次確認 off→on，不重新啟動已取消的一輪。
- 確認 off 時只取消本輪尚未執行的 off，包括改過時間的那筆，不刪除另建的未來手動排程。
- 若明確把本輪排程改成 on／調溫，它已不是關機排程，確認 off 時只結束其 cycle、保留該未來動作。
- 下次 on 依當時 Sheet 設定產生新的一筆。未知／失敗的指令不重送，也不能藉編輯將它重新排入；可移除紀錄再自行新增。
- 自動與另外新增的手動排程依各自時間執行；不再因另有手動 off 隱藏自動列。

## 持久化與相容

既有排程指令分頁同時保存 cycle：來源「自動（HA）」、參數 `_auto_hours`、`_auto_edited`、`_auto_deleted`、`_auto_closed`。
內部 metadata 不傳 HA，客戶端編輯不能改掉這些標記。未結束的已取消／已執行／未知列保留，避免重建。
確認 off 後，成功／取消紀錄移至排程封存，不必等同設備的其他未來排程結束。待確認／失敗保留供檢查；移除時封存原結果。
修改／刪除與背景觀察、執行、封存共用單程序鎖；寫入前即時定位唯一列，不使用 request 早先的列號。
Sheets 不提供跨程序或手動外部編輯的交易保證，不能直接增加 HB workers。
v1.56 已存在的計時列保留期限；舊 `_auto_paused` 暫停列恢復為一般可編輯排程，不覆寫日期時間。
使用者刪除必須經排程功能；直接從 Sheet 刪除 cycle 紀錄會失去本輪去重狀態。

`GET /api/ac/auto-off` 保留完整 key 的診斷讀取；舊 `POST` 回 410，不再保存時數。Dashboard BFF 與設定面板已移除。
非 HA 空調保留既有 handler 機制；防黴與回饋不恢復給 HA 空調。

## 限制與部署

需 HB 運行；HA 離線或狀態不確定不代表 off，不清理／重置／下令。恢復後沿用原期限，逾期超過兩小時依一般排程標過期。
兩次觀察間或離線期間完整發生的 off→on 無法重建；SwitchBot Cloud 狀態是最後指令，不是真實 IR 電源回讀。
先部署 HB，再部署 Dashboard 1.57.0，不需更新 HA 整合。既有家庭時數與未到期計時列不需搬移。
離線測試與 demo 不操作家庭家電；實體到期關機留待使用者驗收。
若退回 v1.56，舊後端無法辨識刪除／編輯的新語意；應先停用排程執行並檢查本輪紀錄，不可把舊程式直接部署到仍在執行的新資料上。
